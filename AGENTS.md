# NotifyKit — agent notes

- The no-fake-success rule is load-bearing: a tray call reports success only when the Shell_NotifyIconW call itself succeeded. On non-Windows the tray half returns ERR_NOT_SUPPORTED — never stub in a "pretend it worked" path so cross-platform demos look nicer; a host that believes a notification was shown when nothing happened will not retry, queue, or log, and the user silently misses the message.
- Coalescing applies to PENDING entries only. An entry that has been drained to history never absorbs new repeats — if it did, a host polling on a timer would miss notifications that arrived after its last poll, because they would have merged into an entry it already consumed.
- Bounds drop the OLDEST entry and count the drop in `dropped`. Changing that to drop-newest, or dropping without counting, breaks the stats contract the header documents ("nothing vanishes silently").
- The text budgets are the real fixed-buffer sizes of NOTIFYICONDATAW (szInfoTitle 64, szInfo 256, szTip 128 UTF-16 units INCLUDING the NUL). Truncation cuts on a char boundary — a surrogate pair is never split — and the truncated flags in the result JSON are part of the contract. Do not "fix" an overflow by enlarging the struct arrays; the shell's buffers are the sizes they are.
- The NOTIFYICONDATAW struct in platform.rs is the base V3 layout (ends at guidItem; no hBalloonIcon) and cbSize is `size_of` of that struct. Adding fields without updating the documented layout, or hardcoding a cbSize from a different struct version, makes the shell misread the struct.
- Every extern block in platform.rs MUST carry #[link(name = "...")] (shell32 / user32 / kernel32). Without it the build fails at LINK time with LNK2019 — check and clippy cannot catch it; CI's real Windows build can.
- Stock icon ids are MAKEINTRESOURCE values passed as pointers to LoadIconW with a NULL instance; the returned handles are system-owned and must never be destroyed. IDI_WARNING is IDI_EXCLAMATION (32515) and IDI_INFORMATION is IDI_ASTERISK (32516) — the numeric ids are easy to transpose; the named constants in platform.rs are the checked values.
- The JSON engine (src/json.rs) is the family design — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins. Unknown config/item keys are likewise rejected on purpose.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate, and a real on-screen balloon is a field test on a real desktop, not something CI or a VM can claim.
